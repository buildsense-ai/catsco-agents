# CatsCo 会议纪要格式规范（内部）

当用户要求整理会议记录、生成会议纪要、提炼决议与待办时，应用以下全部规则。

## 一、信息分拣原则

原始记录里的每一句话，归入且仅归入一个桶：

| 桶 | 判定 | 去向 |
|---|---|---|
| 已达成的结论 | 有明确拍板（"就按 X 做""定了用 Y"） | **决议** |
| 下一步动作 | 有人要去做某件事 | **待办** |
| 悬而未决 | 讨论了但没有结论、有分歧 | **待确认** |
| 卡点 | 明确会阻碍推进的外部依赖/风险 | **风险与阻塞** |
| 闲聊/过程 | 背景铺垫、寒暄、重复讨论 | 丢弃 |

判断不了归"待确认"，**禁止猜测**。

## 二、决议写法

1. 一句话说清"决定了什么"；能写"决定 + 范围/边界"就不写过程。
2. 保留输入里的理由（如有）：`按方案 B 执行（原因：迁移成本更低）`。
3. 编号列表；决议超过 8 条时按重要性取前 8 条，其余合并同类项。

## 三、待办写法

1. 格式：`<动词开头的动作>` + 负责人 + 期限（表格三列）。
2. 动词示例：实现、修复、验证、调研、对齐、交付、确认、补充。
3. 负责人只写输入中出现的人名/角色；未提及留空，**不许指派**。
4. 期限只写输入中出现的日期或相对时间（"下周一"）；未提及留空。
5. 同一人多个待办不合并（便于逐条跟踪）。

## 四、语言风格

1. 陈述事实，不做评价（禁止"讨论得很充分"这类过程性形容）。
2. 不使用行业黑话：赋能、抓手、闭环、拉通、对齐颗粒度。
3. 日期用 `M/D` 格式；人名用姓名全拼或中文名。
4. 中英混杂输入：保留专有名词原文（系统名/接口名/版本号），其余按输入主语言输出。

## 五、审查清单（输出前逐条自检）

- [ ] 每条决议都能在原文找到依据；没有编造
- [ ] 每条待办是"可执行动作"，不是"关注/跟进"类空动作
- [ ] 负责人与期限只来自输入，未指派
- [ ] 悬而未决的都进了"待确认"，没有伪装成决议
- [ ] 专有名词、数字、日期原样保留
