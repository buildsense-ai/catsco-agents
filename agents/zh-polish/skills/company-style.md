# CatsCo 中文书面语规范（润色场景）

润色中文文本时，按下表逐项检查。优先级：**保事实 > 保原意 > 改风格**。

## 〇、反编造红线（最高优先级，先于一切风格修改）

1. 删除黑话/空话/情绪表达后，**如果原文没有给出具体事实，就整句删除或退为原文已有的中性表述**；**禁止补造**原文没有的机制、数字、因果、流程（如把"赋能了上架效率"改写成"上架流程由串行改为并行，耗时显著下降"——机制是编的）。
2. 改写动词时不得升级确定性："准备上线" ≠ "已上线"；"看起来解决了" ≠ "已修复"。
3. 拿不准原文意图时：保留原文措辞不动，并在修改说明标注"（语义不明，按原文保留）"。
4. 自检：润色稿中每一句陈述，都能在原文找到对应；找不到 → 删。

示例：
- ❌ `赋能了所有 agent 的上架效率` → `上架流程由串行改为并行，单次耗时显著下降`（编造机制与数字）
- ✅ `赋能了所有 agent 的上架效率` → `改善了所有定制应用（服务化 agent）的上架效率`；或整句删除
- ❌ `效果显著` → `错误率从 3% 降到 0.5%`（编造数字）
- ✅ `效果显著` → 删除（或提示"如需保留效果描述，请提供具体指标"）

## 一、禁止清单（见到必改）

| 类别 | 禁止 | 改为 |
|---|---|---|
| 行业黑话 | 赋能、抓手、闭环、拉通、对齐颗粒度 | 具体动作描述（如"已完成 A→B 串联验证"） |
| 空评价 | 非常成功、效果显著、大幅度提升 | 有数字写数字；无数字直接删 |
| 情绪表达 | 很遗憾、非常抱歉、辛苦大家 | 陈述事实 + 下一步 |
| 冗余套话 | 值得一提的是、众所周知、不难看出 | 直接删 |
| 中英混排不当 | 这个 feature 很 nice | 统一中文（专有名词除外） |

## 二、病句类型与修法

1. **主语缺失/错位**：补主语或改被动——"已经上线了" → "v1.5.9 已上线"（明确对象）。
2. **动宾搭配不当**："解决问题" vs "处理问题"——按语境选准确动词（修复 bug / 排查故障 / 处理投诉）。
3. **成分残缺**：缺"的/了/着"导致歧义时补齐。
4. **语序问题**：时间/地点状语前置，长定语拆分。
5. **一逗到底**：超过 3 个分句必断句。

## 三、标点与格式细则

1. 中文文本用全角标点；数字与英文单词两侧不加空格（"3 个"除外——中文数字间按原文）。
2. 书名号《》用于文书名；代码/变量/文件名用 `inline code` 不加引号。
3. 顿号用于并列词，逗号用于分句；"等、等等"不与省略号连用。
4. 破折号——占两格，不写成连续两个连字符。

## 四、术语与专名

1. 按知识库术语对照表统一（cats 平台 → CatsCo 主站平台 等）。
2. 数字/日期/版本号（v1.5.9、PR #637、3/15）**逐字保留**。
3. 人名用姓名全拼或中文名。
4. 术语表未收录的专有名词：保留原文，并在修改说明标注"（术语表未收录，按原文保留）"。

## 五、修改说明的写法

- 格式：`原文 → 修改后` + 一句话原因。
- 原因引用本规范条款（如"禁止清单：空评价"、"〇：反编造红线"）。
- 标点/错别字合并一条：`标点全文改为全角；修正错别字 3 处（已直接体现在润色稿）`。
- 只列实质性修改；纯风格微调不逐条列。
- **无需标注"术语表未收录"的情况**：版本号（v1.6.0）、PR 编号（PR #637）、日期（M/D）、数字——这些按本规范第四节"逐字保留"处理，属既定规则，不算术语表缺漏。
- 术语表未收录的**专有名词**才标"（术语表未收录，按原文保留）"。
