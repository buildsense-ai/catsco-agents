# CatsCo 周报写作规范（内部）

本规范用于统一公司内部周报的语言风格与结构。当用户要求撰写、润色或审查周报时，应用以下全部规则。

## 一、语气与立场

1. 第一人称视角写团队工作（"我们完成了…"），个人产出用中性描述（"推进了…"）。
2. 陈述事实，不做自我评价（禁止："非常成功"、"效果显著"等无数据支撑的形容）。
3. 失败与延期如实写，重点写"影响 + 下一步"，不写情绪（禁止："很遗憾"、"非常抱歉"）。
4. 不使用行业黑话：赋能、抓手、闭环、对齐颗粒度、拉通、链路打通（如确需表达"打通链路"，写"已完成 A 到 B 的串联验证"）。

## 二、结构模板（标准五段）

```
# 周报（M/D–M/D）

## 本周完成
- <动作> + <对象> + <结果/影响>
（按重要性降序，不超过 8 条；跨天的事项合并为一条）

## 进行中
- <事项>：当前进度 <百分比或里程碑>；预计 <完成时间>

## 风险与阻塞
- <风险描述>：影响 <范围>；需要 <支持或决策>
（没有则写"无"）

## 下周计划
- <可交付的结果>（从"进行中"与"风险"自然延伸，3-5 条）

## 数据/指标（可选）
- 只在有真实数字时添加（如"线上错误率 0.3%→0.1%"）
```

## 三、逐条写法

1. 每条必须包含**动作 + 对象 + 结果**三要素；缺少"结果"时写"进行中"而不是硬凑完成。
2. 保留原始输入中的**具体数字、专有名词、日期、版本号**，一个都不许丢。
3. 动词优先用：交付、上线、修复、验证、完成、排查、调研、对齐（对人，不用于系统）。
4. 技术细节压缩为一句；确需展开时在条目后加括注（不超过 20 字）。
5. 同一条目不写两遍；相似事项（如"部署 A"和"部署 B"）合并为"部署 A、B 至生产"。

## 四、时间与量化

1. 日期用 `M/D` 格式；跨周事项标注起止（"6/1 起"）。
2. 百分比只写估算来源明确的值（"约 60%"），禁止编造精确数字。
3. 时长写法："约 2 小时"、"半天"。

## 五、审查清单（写作后自查）

- [ ] 每条都有动作+对象+结果？
- [ ] 原始数字全部保留？
- [ ] 没有黑话与自我评价？
- [ ] 风险段是真实卡点（不是流水账）？
- [ ] 下周计划可交付（而不是"继续推进"）？
